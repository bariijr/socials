How should the master-detail pages behave below tablet width?

This applies to every page built on the two-pane pattern (AdminTrips, AdminAssets' 9 tabs) — a list on the left, a persistent detail/edit panel on the right. On a narrow screen, both panes can't fit side by side.

A · Stack (navigate away)

Tapping a list item replaces the screen entirely with the detail/edit panel, full width, with a Back control. Classic mail-app pattern — one thing on screen at a time.

B · Bottom Sheet

The list stays visible underneath; tapping an item slides the detail/edit panel up as a sheet over it. Dismiss to return to the list without losing scroll position.

C · Tab Switcher

Both panes exist on screen at all times; a small tab control at the top switches which one is showing. Selecting a list item auto-switches to the Detail tab.

For reference — desktop stays exactly as it is today (both panes side by side, list ~320-384px wide, detail filling the rest). This choice only affects what happens below the tablet breakpoint.
